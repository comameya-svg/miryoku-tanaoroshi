## 1. はじめに
- **目的（OBJ-001）**: サミット参加者が、9マス発想法で自分の「魅力」と「課題」を書き出し、掛け合わせて「そこにしかない個性」を一文にできる。
- **OBJ-002**: 体験の最後に横田さんの「無料棚卸しセッション」へ自然につなぐ。
- **スコープ**: research/intake_sheet.md のスコープ表どおり（IN/OUT/DEFER）。
- **根拠ID**: EV-Q1〜EV-Q7 = intake_sheet.md の各回答。EV-A/B/C = research_v1/v2。

## 2. 全体説明
- **USR-001 参加者**（スマホ中心、ITは得意でない人も含む）／**USR-002 横田さん**（講演で紹介、セッション申込を受ける）
- **FLOW-001**: 開く → 名前を書く → テーマを選んで8マス書く（繰り返し）→ 全体を見る → 掛け合わせて一文 → カード保存 → セッション申込
- **成功指標**: 初めての人が説明なしで、5分以内に一文を作れる（E2E-01で確認）

### 画面（空状態の文言まで）
- **SCR-01 ホーム（3×3）**: 中心「あなたの名前・事業名」。空状態の上部文言「まずは真ん中に名前を書いて、気になるテーマから埋めてみましょう」。常時「全部埋めなくてOK。魅力1つ・課題1つで掛け合わせできます」と掛け合わせボタンを表示（REV-R1-003）
- **SCR-02 テーマ入力**: テーマ名＋説明、8マス（ヒント付き）、「前のテーマ／次のテーマ」「マスに戻る」
- **SCR-03 全体図（9×9）**: 閲覧専用。ブロックをタップするとSCR-02へ
- **SCR-04 掛け合わせ**: 魅力選択・課題選択・相手入力・一文・文型切替・シャッフル・カード作成。空状態はFR-MIX-005の案内
- **SCR-05 結果カード**: プレビュー、中身表示切替、保存、共有（対応時）、セッション申込
- **SCR-06 記入例**: じゅんちゃんの9×9と一文（閲覧専用）

## 4. データ（DATA-001 保存データ）
```
{ v:1, center:string(≤40), cells:{ [themeId]: string[8] (各≤40) },
  mix:{ m:{t,i}|null, k:{t,i}|null, who:string(≤20), pattern:0|1|2 },
  card:{ showText:boolean }, savedAt:ISO8601 }
```
- キー: `miryoku-tanaoroshi:v1`。テーマ定義（ID・名前・種類・ヒント）はコード側の定数（DATA-002）。

## 5. 非機能要件（ISO 25010）
| ID | 特性 | 要件 | 基準 |
|---|---|---|---|
| NFR-USE-001 | 使用性 | 幅375pxで横スクロールしない | scrollWidth ≤ 画面幅 |
| NFR-USE-002 | 使用性 | タップ領域は44px以上 | 主要ボタン・マスの高さ≥44px |
| NFR-PERF-001 | 性能効率 | 外部依存はGoogle Fontsのみ、自前JS合計60KB未満 | ファイルサイズ計測 |
| NFR-SEC-001 | セキュリティ | 入力値を外部に送信しない | コードにfetch/XMLHttpRequest/sendBeaconがない |
| NFR-SEC-002 | セキュリティ | 利用者の入力をHTMLとして解釈しない | innerHTMLへ利用者入力を渡さない（textContentのみ） |
| NFR-A11Y-001 | アクセシビリティ | 全入力欄にラベル、本文コントラスト4.5:1以上 | 目視＋計算 |
| NFR-COMP-001 | 互換性 | 最新のChrome/Edge/Safari（iOS含む）で動作 | E2E（Chromium）＋Safari差異の既知リスク記録 |
| NFR-THEME-001 | 使用性 | OSのダークモードで読みやすく表示 | prefers-color-scheme: dark |
| NFR-MAINT-001 | 保守性 | テーマ・ヒント・文型・申込URLは1ファイル（config.js）で変更できる | コード確認 |
